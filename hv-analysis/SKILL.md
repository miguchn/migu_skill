# 横纵分析法 · 轻量完整版

> 方法论借鉴自 [数字生命卡兹克](https://github.com/KKKKhazix/khazix-skills) 的横纵分析法（历时-共时双轴分析）。原版产出 1-3 万字 + PDF 的重型深度报告；**本 skill 是轻量完整版：30-60 分钟、2000-8000 字、结构化 Markdown 交付**。小，但是完整闭环——搜索、分析、写作、自检、交付一个不少。需要重型报告时用原版。

纵轴追时间深度，横轴追同期广度，两轴交汇出判断。

## 流程总览

定对象 → **实时信息收集（命脉）** → 纵轴 → 横轴 → 交汇 → 交付 + 质检

---

## 第 0 步：定对象

确认研究对象 + 类型。类型决定侧重：

- **产品**：纵看版本迭代/技术路线/用户增长；横看功能/性能/体验/定价
- **公司**：纵看创始团队/融资/战略转向；横看商业模式/份额/组织
- **概念**：纵看起源（谁提出/基于什么理论）/流行与争论；横看相近概念区别/各自适用场景
- **人物**：纵看经历/关键决策/成长曲线；横看同领域人物的路线与风格差异

用户已给明确对象就不追问，直接开始。

---

## 第 1 步：实时信息收集（命脉）

研究质量八成由这一步决定。**必须实时搜索，禁止仅凭模型记忆硬写。**

### 两路搜索清单

**纵路**（历史线）：`对象名 + 创始人/发起者`、`对象名 + 发布/成立/提出`、`对象名 + 版本历史/changelog`、`对象名 + 融资/转折/争议`

**横路**（竞争线）：`对象名 + alternatives/竞品/对比/vs`、`对象名 + 用户评价/口碑/吐槽`、赛道名 + 格局/市场

每路至少 2 组关键词、搜两轮以上；第一轮发现的线索（人名、版本名、事件名）进第二轮关键词。

### 工具适配

- **WebSearch** 发现来源与线索；**WebFetch** 已知 URL 定向深读
- **学术型对象必查 arXiv**：`curl -s "https://export.arxiv.org/api/query?search_query=all:关键词&max_results=10"`
- **开源项目型对象优先结构化元数据**：gh/GitHub API 查 stars、pushed_at、license、releases——比读 README 更可靠、更抗噪音

### 来源与时效硬规则

1. 一手优先：官方博客/Release Notes/创始人发言 > 权威媒体原创 > 转载聚合；多源引用同一错误=循环印证假象
2. **时效硬规则**：关键事实优先采用近 12 个月来源；引用必标日期；超 12 个月的旧信息谨慎使用并标注"较早来源"
3. 事实、推断、观点分开写；冲突信息并列呈现

### 充分性自检与搜索结束条件

- 纵：能讲出一个有因果的完整故事吗？有无明显信息断层？
- 横：主要玩家漏了吗？每个对比对象的信息够吗？
- 源：关键事实有可靠来源吗？有没有单源就下判断的？

先判断缺口是否影响核心问题。影响核心结论的缺口应定向补搜；完成规定搜索并追查关键线索后，仍不可获得的信息标为“暂缺”或“无法核实”，说明它限制了哪些判断，然后完成其余分析与交付。不得为了通过检查编造事实或强行补齐因果故事。工具不可用时，尝试可用的等效检索方式；仍受阻则说明未完成的研究项，不把未检索的内容标为已核实。

---

## 第 2 步：纵轴（800-2000 字）

三要素，一次问透：

1. **起源**：什么背景和需求下诞生，关键推动者是谁，为什么是他们
2. **转折**：重要转折、成功、失败，按因果讲，不按年份罗列
3. **路径依赖**：哪些早期选择变成今天的能力或包袱，如何约束未来选择

**叙事体，不是年表流水账**：有起承转合，"为什么在这个时间点爆发"要讲出铺垫和转折。

---

## 第 3 步：横轴（800-2500 字）

先判竞品场景：

- **A 无直接竞品**：为什么没有（品类太新/壁垒太高/市场太小）？最可能从哪冒出竞争者？
- **B 少量（1-2）**：逐一深入对比
- **C 充分（3+）**：选最具代表性的 3 个，其余一笔带过

对比至少覆盖：统一维度下的强项/短板/独特性；用户选它的真实理由与放弃理由（引用真实用户声音，不照官方宣传）；生态位（填补空白还是正面竞争）。

---

## 第 4 步：交汇判断（300-800 字）

不写前文缩写版，产出新判断：

1. 历史如何塑造了当下的竞争位置（路径依赖→ present 约束）
2. 今天的核心优势/劣势，各能追溯到哪个历史节点
3. 未来路径 1-3 条（视情况，不凑数），每条给前提和预警信号

---

## 风格红线（3 条）

1. 叙事驱动不罗列；用具体细节和数字代替空泛概括（不写"快速增长"，写"从 X 到 Y"）
2. 敢下判断，但先摆事实再给判断；推测明确标"我的判断/推测"
3. 搜不到写"暂缺"，绝不编造；AI 味套话禁用（"首先...其次"、"综上所述"、"赋能"、"在当今 AI 时代"）

---

## 交付格式

结构化 Markdown，保存到用户工作目录，命名 `[对象]_横纵分析.md`：

```
> 研究对象：XX | 类型：XX | 调研日期：YYYY-MM-DD

## 一句话结论
## 关键时间线（表格：时间 | 事件 | 意义）
## 纵向分析：起源、转折与路径依赖
## 横向对比（表格：维度 | 对象 | 竞品1 | 竞品2）
## 交汇判断
## 仍待确认的问题
## 信息来源（URL + 访问日期，一手来源标 ★）
```

时间线辅助定位事件，不替代纵向分析正文。总篇幅以 2000-8000 字为参考，各部分篇幅随资料量调整，不为达到字数下限重复内容。

---

## 质检自检（交付前逐项检查）

必须检查并如实处理每项；按上述搜索结束条件确认无法获得的信息，可以用“暂缺且已说明影响”记录检查结果，不能视作已核实。完成可执行的研究与交付，并明确仍受阻的部分。

- [ ] 信息是实时搜的，不是凭记忆？关键事实标了来源和日期？
- [ ] 纵轴是叙事故事，不是年表？
- [ ] 横轴用户视角引用了真实声音，不是官方宣传复读？
- [ ] 交汇产出了新判断，不是前文缩写？
- [ ] 搜不到的诚实标了"暂缺"？
- [ ] 一句话结论在第一屏？
